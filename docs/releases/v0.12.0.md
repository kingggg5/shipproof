# ShipProof v0.12.0 — Polyglot Precision and PHP2Shell Advisories

ShipProof v0.12.0 integrates the TypeScript/JavaScript and Roblox/Rust cohorts,
adds a dated PHP2Shell declared-version advisory, and corrects known noisy rules.
All **652 executable rules** have positive, negative and adversarial assurance
contracts. The default remains offline, read-only and dependency-free beyond
Node.js/Python; no scanned source, browser, PHP runtime or container is executed.

## Highlights

- `SP674`–`SP682`: import-aware JS/TypeScript configuration advisories for JWT time
  and key-type opt-outs, short AES-GCM tags, direct unsafe Buffer reads, lenient
  HTTP parsing, Next.js private-IP image targets, Electron privilege/origin
  boundaries and Puppeteer sandbox opt-outs. `.mts`/`.cts` join the source walker;
  older rules retain their documented suffix lists.
- `SP671`–`SP673`: bounded Roblox/Luau remote-source signatures and explicitly
  zero-initialized Rust references; direct reqwest TLS switches extend `SP104`.
- `SP683`: offline PHP2Shell version evidence for exact `.php-version`, single
  `.tool-versions` PHP pins and final static official PHP FPM/Apache image stages.
  It records **CVE-2026-109618** and **CVE-2026-109619**, disclosed 21 October 2026.
  Upstream fixes are 8.2.35, 8.3.36, 8.4.27 and 8.5.12. Each branch is compared
  separately. Vendor backports, actual deployment and exploitability require
  independent evidence; Composer constraints do not establish a runtime version.
- `SP668` now checks syslog's second argument, not its priority, with bounded
  lexical filtering for code-like text. `SP670` requires an explicit DTD-parser /
  external-resolver combination consumed by XmlReader; DTD parsing alone and
  null/throwing resolvers are not labeled XXE.
- `SP591` excludes erased type-import declarations and misleading client strings;
  its observable bundling concern is a medium advisory, not a critical secret-leak
  assertion. Inline-only type imports remain compiler-dependent and unresolved.
- Retire `SP429`: Express JSON parsing already has a default size limit. The ID
  remains reserved. Correct the Dart custom-trust-store false positive in `SP104`.
- Patch the optional MCP development dependency tree: SDK 1.32.1 and fixed URI,
  HTTP-framework, proxy/IP-classification packages. Runtime dependencies remain
  zero; stdio handshake and the missing-optional-peer path remain release gates.

## PHP2Shell evidence boundary

The PHP project's advisories rate the upstream issues critical, but `SP683` is a
medium advisory about a **declared version**, not a confirmed vulnerable host.
Floating tags, custom image registries, digest-only identities, vendor-suffixed
versions, unknown branches, dynamic build arguments and heredocs are unresolved.
CLI-only PHP images are outside this web-runtime signature. This is not a live
vulnerability feed, package inventory or substitute for vendor patch verification.

Apply a supported upstream update or a verified vendor backport and restart web
workers. An application-level validator, WAF, disabled upload-progress setting or
hidden diagnostic output is not presented as a complete PHP runtime patch.

Primary sources: [PHP announcement](https://www.php.net/archive/2026.php#2026-10-21-5),
[OOM advisory](https://github.com/php/php-src/security/advisories/GHSA-w8hw-w9fx-j79w),
[stale-state advisory](https://github.com/php/php-src/security/advisories/GHSA-6wmf-4rv5-p3rp).
The snapshot was reviewed on 22 October 2026.

## Compatibility and migration

Public commands, JSON/SARIF schema versions and `0/1/2` exit semantics are unchanged.
`SP591`, `SP666`–`SP683` and the new Rust variant of `SP104` are advisory regardless
of the selected severity/proof floor. These checks do not become release blockers
by lowering that floor. Existing blocking secret and confirmed-proof gates remain.

Review baselines when upgrading: narrowing or retiring a detector can remove
findings; corrected argument/configuration checks can add previously missed ones.
No IDs are reused and published historical catalogs retain their tagged counts.

Review-first cohorts emit normalized configuration/behavior evidence rather than
unrelated arguments or comments. Their terminal/Markdown/fix-prompt contexts do not
re-read neighboring source, which may contain credentials. Locations remain usable
for local inspection; affected fingerprints may change. This boundary covers
`SP591`, `SP666`–`SP683` and the advisory Rust TLS extension, not a universal claim
that arbitrary private source text can be classified as non-sensitive.

Maintainer research notebooks, expansion plans and historical release notes remain
available in the source repository and are omitted from the npm runtime artifact.
The exact allowlist and existing 500,000-byte packed / 1,870,000-byte unpacked
package ceilings are retained. This pre-1.0 release follows the repository's
prerelease workflow policy; npm registry publication remains separately manual.

## Verification

Required gates are the complete lint/Node/Python suite, real-walker and CLI/SARIF
parity, rule assurance/contract freshness, high-gate self-scan, precision trend,
dependency audit, bounded Python/TypeScript benchmarks, exact package contents and
isolated consumer smoke tests. Source is pushed before tagging; GitHub CI and the
Release workflow must confirm the exact commit and attach the tarball/checksum.

Local evidence and residual limitations are recorded in
[the release report](https://github.com/kingggg5/shipproof/blob/v0.12.0/research/release-0.12.0-report.md). Directed regression
cases and a clean scan do not establish a universal zero false-positive rate.
