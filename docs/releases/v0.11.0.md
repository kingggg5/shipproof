# ShipProof v0.11.0 — Proof Thresholds and Fail-Closed Coverage

ShipProof v0.11.0 turns the post-0.10 precision and trust-boundary work into the default gate. The default workflow remains read-only, offline, deterministic, and dependency-free. This release does not bulk-promote research candidates or publish a public precision percentage.

## Highlights

- Default `BLOCK` now requires L1 proof or an allowlisted L0 finding such as a high-confidence secret or `DEBUG = True`. Remaining high L0 findings still appear, but the verdict is `REVIEW`. `shipproof check` will not honor a floor below L1. Auto library mode downranks application-oriented rules when no application entrypoint is visible; nested `wsgi.py` / `asgi.py` modules no longer force application profile. SP061 is advisory and does not change the verdict.
- Selected-source coverage is a ledger. Unreadable files, oversized sources, and uninspected containers make coverage incomplete; a would-be pass becomes `CONDITIONAL` and the completeness gate exits `1`. Repository scans, the Action, and MCP fail closed by default; `--allow-incomplete` is an explicit exploratory override and is never used by `check`.
- Baselines upgrade to auditable suppression format version 2. Fingerprint objects and human-authored glob rules require non-empty reasons; legacy string fingerprints keep loading. `--show-suppressed` works across JSON, Markdown, terminal, and SARIF.
- Python, Git, Go, and Rust probes resolve only trusted absolute host executables. The TypeScript adapter requires explicit consent plus a repository-contained regular compiler. Scan coverage, parser/line/finding/baseline/JSON inputs, report writes, policy gates, and terminal output fail closed or stay bounded across CLI, Action, pre-commit, and MCP channels.
- A revision-pinned clean-corpus evaluator and finding-label store score precision only on reviewed rows. Weekly and release workflows enforce `benchmarks/precision-thresholds.json`. Head-to-head labels are schema 3 with a 0.95 line-level gate on the ShipProof self-leg. OWASP Benchmark stays unbundled after a GPL license review.
- Opt-in maintainer lanes stay off the default scanner path: bounded ZIP/Office inspection (`--inspect-archives`), an advisory shadow harness for research prototypes SP5301/SP5951/SP6309, a Skill/MCP capability inventory, and versioned external-evidence import that keeps original rule IDs and exits `2` on malformed envelopes.
- Precision updates cover Skill/MCP rules, SP631 Edge-runtime false positives, workflow/Git/BullMQ/fetch/JSON-source context, and authored eval-dataset files treated as test scope. `.jsonl` files are scanned as text. All 635 executable scanner rules remain under the machine-readable assurance contract.

## Evidence boundary

The three promotion prototypes are not executable ShipProof rules and do not change the 635-rule public catalog. Shadow fixtures show that a detector shape is testable; they do not establish representative precision.

Clean-corpus measurements and labeled false positives apply only to the pinned packages and reviewed rows. Unreviewed real-world findings stay unreviewed. This release does not claim a public precision percentage.

## Compatibility

The supported public commands remain `check`, `scan`, `explain`, `gate`, `labs`, `init`, `config validate`, `doctor`, and `mcp`. Hidden legacy aliases continue to emit migration warnings in 0.x. When the package major reaches 1, the parser rejects those aliases with exit code `2` and points to their replacements.

Exit codes remain `0` for pass, `1` for gate failure, and `2` for invalid or unavailable evidence. Existing v1 JSON schemas remain compatible. `confidence` stays risk confidence; `match_confidence` and `proof_level` are additive. `scan.profile` and `security.block_min_proof` are additive policy fields.

## Verification

Before a tag is created, the release must pass the complete lint/test/package/consumer suite, schema and command goldens, the direct high-severity self-scan, checked-in precision-threshold comparison, and controlled head-to-head thresholds. Publishing to npm remains a separate maintainer action.
